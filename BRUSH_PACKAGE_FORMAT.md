# Sketch3D brush packages

Sketch3D imports and exports one native brush definition per `.brush.json`
file. Version 1 is a self-contained JSON package for brush settings. Version 2
can embed one bounded PNG tip. Packages never contain scripts or external file
references. Built-in brush shapes and procedural texture kinds are represented
by the app's native brush model.

Both versions preserve graphite and charcoal texture settings, continuous-alpha
masks, stipple and spray dab settings, pressure opacity, and tilt-shading
controls. They also preserve the native parallel-strand settings used by rake
and bristle brushes, plus timestamp-based airbrush flow. The bounded square,
triangle, and star tube profiles are generated by the app and need no external
assets.
Readers predating these brush kinds will not understand these package settings.

The top-level object contains `format: "spatial-sketch-brush"`, `version`, and
a `preset` object with `name`, `brush`, `radius`, `color`, and `stabilization`.
Version 1 remains settings-only and imports unchanged. Version 2 adds
`tip_asset`, containing `id`, base64-encoded `png`, `[width, height]` `size`,
and optional human-readable `provenance`. The brush's `tip_asset_id` must match
the asset ID. Version 2 without a tip is also accepted for forward-safe
versioned settings.

Tip IDs use 64-bit FNV-1a over the exact PNG bytes. The ID is a stable content
fingerprint for deduplication, not a security signature. When IDs match, the
library compares PNG bytes and rejects a collision rather than merging
different images. Export and import preserve the source PNG bytes. The browser
preview shows the original color and alpha without tinting. On a stroke, the
stored brush color multiplies PNG RGB, while PNG alpha is preserved and then
multiplied by brush opacity and pressure; tint cannot make transparent pixels
opaque.

Only PNG is accepted. The decoder supports PNG color types, bit depths, and
alpha forms accepted by the bundled `image` PNG decoder; assets are decoded to
RGBA for preview and rendering. Each PNG is at most 512 KiB and 512 × 512
pixels. A library or drawing holds at most 64 unique tips, 16 MiB of encoded
PNG bytes, and 4,194,304 total pixels (16 MiB worst-case decoded RGBA). The
complete package is limited to 1 MiB and the local library file to 32 MiB.
These limits are checked before committing an import or document edit.

Package names and settings use the same limits as local presets. Malformed
JSON, unsupported or corrupt PNGs, unknown format or version, and out-of-range
or non-finite values are rejected without changing the local library. Imported
tips are embedded in the local library and native drawing documents, so later
drawing and recovery do not depend on the package path or original source
image.

Import creates a personal preset with a new local ID. If its name collides
case-insensitively, the imported entry gets an `(imported)` suffix, followed by
a number when needed. Import selects the entry in the library but does not
change the active drawing brush; use the normal **Use preset** action to apply
it. Export serializes the selected preset without its local ID, so the package
can be imported into another library without carrying local identity. Native
drawing insertion merges embedded tips by content ID. Undo removes inserted
strokes while keeping the embedded catalog available for redo and later use.
Backup and recovery snapshots carry the same self-contained document data.
GLB export embeds tip PNG bytes and UV coordinates. OBJ export writes a
`map_Kd` color map and a grayscale `map_d` alpha companion in the MTL bundle;
OBJ has no standard double-sided-material flag, so importer back-face behavior
can vary.

No compatibility with third-party 2D brush formats is claimed. They may lack
the geometry, pressure, tilt, or procedural texture data required by Spatial
Sketch's 3D brushes.
