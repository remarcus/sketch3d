# Portable fill textures

Select one planar fill and choose **Edit fill contour…** to open the detached editor. **Import fill texture PNG…** embeds an image in the document. Apply saves the texture mapping and fill changes in one undoable stroke edit; Cancel removes newly imported image data that is not used elsewhere. Imported assets remain available when an applied texture is undone so redo and recovery retain their source data.

Texture mapping is relative to the fill's normalized contour bounds. Scale U/V, rotation, and offset are stored independently from the fill's solid color and gradient. Repeat wraps both axes; clearing Repeat clamps at the image edge. Tint multiplies image RGB in linear light; opacity multiplies the image alpha and fill opacity. The viewport and GLB use linear filtering. Transparent texels remain transparent in rendering and are excluded from fill picking.

Fill PNGs reuse the document's content-addressed embedded PNG asset catalog. This catalog already supports native save/reopen, recovery, library backup, and native insertion with byte-checked deduplication. PNG assets are limited to 512 KiB and 512 × 512 pixels; the catalog is limited to 64 unique images, 16 MiB encoded, and 4,194,304 total pixels. Unsupported, corrupt, missing, or oversized referenced data is rejected with an import or document-validation error. Older documents omit the optional fill texture and continue to render as solid or gradient fills.

The fill mesh carries mapped UVs and tint/gradient vertex colors. GLB embeds the original PNG and records the mapping, wrap mode, tint, opacity, and linear-filter policy in fill node extras. OBJ export bundles the PNG plus an alpha companion and bakes fill-local mapping into UV coordinates. MTL receives the tint and opacity; `-clamp on` requests clamping where the importing program supports it. MTL does not standardize texture filtering. Applications that ignore MTL clamp or alpha maps may render border, filtering, or transparency behavior differently.
