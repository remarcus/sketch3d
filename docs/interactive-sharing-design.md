# Public interactive artwork sharing — design draft

## Proposed first release

Share a bounded GLB through an unlisted HTTPS link. The app uploads the exact GLB bytes generated by the existing whole-drawing or selected-strokes exporter; it does not upload the native `.sketch.json`, recovery data, reference-board images, source OBJ files, camera bookmarks, or workspace preferences. The confirmation screen should show the chosen scope, GLB byte size, stroke/material counts, and the fact that anyone with the link can view and download the model.

The desktop app remains the editor. A separate static web viewer loads one GLB, supports orbit/pan/zoom and reset-view controls, and reports loading, unsupported-file, network, and size-limit errors. It offers AR only after the viewer user chooses **View in your space**; unsupported devices retain the 3D view. A 10 MiB upload cap is a proposed initial limit, subject to performance checks on representative mobile devices. The existing 128 MiB exporter limit is too high to adopt as a viewer limit without a separate mobile performance pass.

## Lifecycle and ownership

- **Publish:** user reviews a generated preview and explicit upload summary, then confirms. The service returns a high-entropy unlisted URL and a separate management capability.
- **Update:** user previews the replacement GLB and confirms. The service atomically replaces the content at the existing URL; failed uploads leave the previous revision available.
- **Unpublish:** user confirms removal. The viewer URL stops serving the model immediately; retained backups, logs, caches, and deletion timing must be specified by the chosen host.
- The user owns the artwork and authorizes the service to host only the confirmed GLB. Anyone with the unlisted URL can view and download it. No public directory or search listing is included in the first release.
- Without user accounts, management depends on a secret capability stored in the platform credential manager (Windows Credential Manager, macOS Keychain, or Linux Secret Service). It is excluded from drawings, local link metadata, and backups. Account-based ownership would need a separate authentication design.

## Service and operational costs

No hosting provider is selected. The service needs bounded object storage, HTTPS delivery, upload rate limits, per-object and per-owner quotas, abuse reporting, TLS/domain renewal, monitoring, and a deletion path. Cost depends on retained bytes, download bandwidth, request volume, and support/abuse handling; a monthly budget and deletion-retention policy must be approved after pricing a concrete provider. Do not enable publishing until those recurring costs and who pays them are explicit.

### Cost candidate reviewed 2026-11-01 — Cloudflare Workers + R2 (implemented locally, not deployed)

This is the current service adapter for the static viewer plus upload/update/delete API and object storage. It is implemented locally but remains undeployed. This does not authorize an account, billing, or deployment.

- Workers Free includes 100,000 requests per day and 10 ms CPU time per invocation. The current Workers Paid plan starts at $5/month per account and includes 10 million requests and 30 million CPU milliseconds per month; excess usage is $0.30 per million requests and $0.02 per million CPU milliseconds. Static asset requests are free and unlimited. See [Cloudflare Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/) and [limits](https://developers.cloudflare.com/workers/platform/limits/).
- R2 Standard includes 10 GB-month of storage, 1 million Class A operations, and 10 million Class B operations per month, with no internet egress charge. Above those allowances, listed rates are $0.015 per GB-month, $4.50 per million Class A operations, and $0.36 per million Class B operations. See [Cloudflare R2 pricing](https://developers.cloudflare.com/r2/pricing/).
- These rates do not include a custom domain, billing administration, monitoring, abuse handling, or support. R2 usage above its free allowance is billable, so the service would need hard per-model and aggregate storage quotas, expiration, deletion accounting, and usage monitoring before launch. The Workers Free request limit stops excess requests with an error; that does not cap accumulated R2 storage.
- The $5 Workers plan is a possible baseline if the free request/CPU limits prove too small; it is not a total monthly-cost ceiling. No budget, account owner, retention period, or billing account has been approved.

The Worker uses a serialized Durable Object to enforce 900 active objects and 9 GiB total GLB storage, with a 10 MiB per-model cap. Links expire after 30 days; expired URLs return 404 immediately, while R2 lifecycle cleanup can take up to 24 hours. Authenticated delete removes an object immediately. These quotas do not cap request volume or total account charges, and budget alerts are not hard spending caps. Add rate limits and monitoring before deployment.

Pricing changes over time. Recheck the official pages and estimate costs against an approved monthly ceiling before deployment.

## Validation before implementation

Before deployment, name the account/billing owner and abuse-response owner, approve a monthly hard budget and 30-day retention, and add request-level abuse controls. Validate the viewer and GLB limits on low-end Android/iOS browsers, and verify remote lifecycle behavior against the real provider. The desktop app has no service URL configured by default; publishing cannot occur until an operator explicitly configures one.

## Viewer, client, and service implementation

The static viewer is implemented in `web/share-viewer/`, the Cloudflare adapter in `web/share-service/`, and the desktop workflow in `src/share_service.rs` and `src/app/share_ui.rs`. The app prepares the chosen GLB scope and displays scope, byte size, stroke/material/image/OBJ counts, public download visibility, and excluded local data before requiring an explicit acknowledgement. Update has the same preview and replaces the existing URL. Unpublish asks for a second confirmation. Capabilities are stored in the OS credential manager; local JSON stores only service origin and non-secret link metadata. The Worker stores only SHA-256 hashes of capabilities, enforces 900 active objects/9 GiB total/10 MiB per object, and expires links after 30 days.

The viewer accepts a local `.glb` or a same-site HTTPS `.glb` URL, checks the binary glTF 2.0 container before rendering, and provides orbit/pan/zoom/reset controls plus loading and error messages. It rejects external buffer/image URI references in a GLB; shared fetches omit credentials and reject redirects. Local files are not uploaded. The pinned Google `<model-viewer>` 4.4.0 component offers user-initiated AR. The page itself does not record or upload camera/microphone data and announces a 3D fallback when AR is unavailable or fails.

The 14 viewer Node checks, 9 Worker fake tests, formatting, Cargo compile check, and strict Clippy pass. Headless Chrome rendered the real house GLB. Live remote API use, deployed lifecycle and billing, and mobile hardware behavior remain unverified. The service has no configured account or production origin.
