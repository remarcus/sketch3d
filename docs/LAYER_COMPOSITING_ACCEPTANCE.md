# Layer opacity and blend mode acceptance

The `--verify-layers` GPU verifier runs deterministic overlap and cutout fixtures through the scene renderer. It checks Normal, Multiply, Screen, and Add against CPU-computed linear-light reference colors at the center of two overlapping unlit strokes. It repeats the check with a second camera orientation. The verifier also checks the cutout threshold at layer opacity 0.49 and 0.75, and exercises property preview cancellation, one-step apply, undo/redo, recovery serialization, and legacy defaults.

The run writes its exact pixels, adapter, timing samples, and target budget to `verification/layer-compositing/layer-compositing-report.json` (generated output, not source-controlled). On the acceptance run recorded during development, the GPU was an test GPU using Vulkan. All eight mode/camera reference pixels passed; the largest per-channel difference was one 8-bit level. The 0.49 cutout preserved the blue lower stroke (`[80, 153, 243, 255]`), while 0.75 cleared it (`[0, 0, 0, 255]`).

The populated scene has six layers and 48 strokes. Three synchronous render/readback iterations per size produced median end-to-end times of 8,947 µs at 640×360 and 30,832 µs at 1280×720 on that adapter. The verifier also compares every RGBA pixel between the canvas output and the production still/video frame API: all four blend modes match exactly at both sizes (230,400 pixels per mode at 640×360; 921,600 at 1280×720). Video frame generation calls the same `render_png_pixels` API. The production GIF test separately confirms that the encoded animation decodes to moving playback; it does not claim pixel equality after video encoding. These are local wall-clock readings, include GPU readback, and are not isolated GPU timestamp measurements or a cross-device performance guarantee.

## Render-target and export limits

Blend modes reuse the shared scene color, emission, depth, and post-processing targets; they do not allocate a render target per layer. Three additional blend pipeline variants are created per active sample count. A conservative target budget is 68 bytes per output pixel: it covers the common color/emission/depth targets, 4× multisample color/emission/depth storage, and an 8-byte per-pixel allowance for post-processing. This is a planning upper bound, not a measured driver allocation. It excludes shadow maps, texture/mesh buffers, transient driver overhead, and optional post-effect resources. At this budget, 640×360 is 15,667,200 bytes (~14.94 MiB) and 1280×720 is 62,668,800 bytes (~59.76 MiB).

Viewport, opaque-background still, and video frame rendering use `SceneRenderer`; Multiply falls back to Normal for transparent-background artwork because the current fixed-function blend pipeline cannot reproduce Multiply against an absent destination. The GPU fixture validates the shared opaque-background renderer behavior. It does not compare encoded still/video files pixel-for-pixel. GLB records layer mode and its Normal fallback in node metadata; OBJ records the mode in comments and uses its material representation, which cannot preserve destination-dependent blending. These exports therefore preserve useful layer metadata while approximating the canvas appearance.
